## Security Measures Implemented

### 1. Firestore Security Rules (firestore.rules)
- All collections restricted to `allow read, write: if false`
- Server-side operations only via Firebase Admin SDK
- Direct client-side Firestore access denied

### 2. Password Hashing (server.ts, src/lib/security.ts)
- bcryptjs with 12 salt rounds
- Passwords hashed before storage in register action
- Passwords verified with bcrypt.compare in login action

### 3. Rate Limiting (server.ts, src/lib/security.ts)
- Global: 100 requests per 15 minutes per IP
- Auth endpoints (register/login): 10 requests per 15 minutes per IP
- Heartbeat: 60 requests per minute per IP
- Rate limit headers included in responses

### 4. CORS Restricted Origins (server.ts)
- Origins configured via `ALLOWED_ORIGINS` environment variable
- Default: `http://localhost:3000` in development
- Wildcard `*` origin removed

### 5. Input Sanitization (server.ts, src/lib/security.ts)
- Control character removal
- String length limiting
- AppId validation (10 alphanumeric chars)
- License key format validation (MALIK-XXXX-XXXX-XXXX-XXXX)

### 6. CSRF Protection (src/lib/security.ts)
- Token generation on GET requests
- Token validation on POST requests
- Timing-safe comparison
- 1-hour token expiry

### 7. Helmet Security Headers (server.ts)
- Content Security Policy enabled
- X-Frame-Options: DENY
- X-Content-Type-Options: nosniff
- Referrer Policy: strict-origin-when-cross-origin
- HSTS in production only

### 8. API Key Authentication (server.ts, src/lib/security.ts)
- X-API-Key header validation
- Valid keys stored in `API_KEYS` environment variable
- Heartbeat action accepts session-based auth
